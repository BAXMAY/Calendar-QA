System Architecture & Developer Guide

Technical reference for developing, operating, and handing over the UTAC QA Calendar (QMS-CASS). This page consolidates architecture, workflow, schema, business rules, and operational troubleshooting. Facts below describe the checked-in repository; they do not confirm the state of a live Cloudflare environment.

React + TypeScript Cloudflare Worker D1 / SQLite 7 UTAC sites

Operational boundary: wrangler.toml configures a Worker with static assets and a D1 binding. The repository does not configure Cloudflare Pages or a CI/CD workflow. A Git push alone does not run the documented wrangler deploy command.
SECTION 01

Overview & scope

QMS-CASS is a browser-based audit planning and tracking tool for UTL1, UTL2, UTL2A, UTL2B, UTL3, UTL3A, and UTL3T. It supports schedule planning, appointment records, audit results, a searchable table, summary dashboards, master-data management, holidays/restrictions, and activity history.

Use this guide in order: architecture → deployment workflow → data and API → business rules → security and troubleshooting → file references. The separate user guide remains the operator-facing procedure manual.

Client

React 19 + TypeScript, bundled by Vite. Main application state and scheduling operations are in src/useScheduler.ts.

Runtime

Cloudflare Worker entry: worker/index.ts. It serves built assets from dist and handles same-origin /api/*.

Storage

Cloudflare D1 binding DB; schema changes are tracked in migrations/.

SECTION 03

Developer workflow & deployment

3.1 Local setup

  1. Install a supported Node.js version and dependencies: npm install.
  2. For frontend-only work, run npm run dev. This uses Vite and does not exercise the Worker/D1 API by itself.
  3. For end-to-end local Worker testing, run npm run dev:worker; it builds first and then starts wrangler dev. Configure local D1 as needed.
  4. Apply local migrations with npm run migrate:local. Inspect local data before resetting it.
  5. Before release, review the diff and run npm run lint and npm run build.

3.2 Git and release

  1. Create a short-lived branch and keep changes focused; record schema changes as ordered SQL migrations.
  2. Review commit, push, and open a pull request according to company policy. Repository scripts do not declare an automatic deployment pipeline.
  3. Confirm the target account, Worker, D1 database, bindings, secrets, and backup/rollback plan with the IT owner.
  4. Apply remote schema changes deliberately with npm run migrate:remote; do not migrate production as a side effect of a frontend release.
  5. npm run deploy runs npm run build then wrangler deploy. Verify the deployed URL and critical workflows with an authorized account.
Production safeguard: migrations and deployment affect remote resources. Confirm the Cloudflare account and environment before each command; use an approved backup and change window.

Holiday rules are stored by date in custom_holidays. The holiday manager supports application UI changes, including public holidays, shutdown site locks, no-customer-audit rules, and working-day overrides. The current UI does not provide Excel/CSV holiday import. XLSX export exists in the frontend where the relevant table/export control is available.

SECTION 06

Core logic & poka-yoke rules

Appointment status and appearance

Derived stateColorCurrent rule summary
Incomplete DataRedRequired data is incomplete.
New DataPurpleComplete data within the new-record age window.
Updated DataBlueRecently edited complete data, prioritized per resolver logic.
Pending ResultAmberPast appointment with result still pending after the age threshold.
Complete DataGreenComplete data outside the new/updated/pending conditions.

Status is derived by resolveAuditStatus / status helpers in src/types.ts. Cards and rows use soft status fills, white status text treatment where configured, and site-color left accents. Site colors are configurable via options; current defaults cover all seven UTL sites. Treat the resolver code as authoritative when a record appears unexpected.

Calendar day rules

  • Public Holiday: blocks Customer and Internal Audit scheduling for the day.
  • No Customer Audits: blocks Customer Audits (CS); Internal Audits (IA) remain allowed.
  • Shutdown Plant: blocks CS; IA is allowed only for sites that are not locked by that rule.
  • Working Day: explicitly overrides a built-in holiday to make it schedulable.

Rules are represented by custom_holidays and interpreted in src/holidays.ts. Shutdown lock selection is explicit; verify the selected sites and date before saving.

Validation and non-destructive rules

Appointment validation and date-cell constraints are implemented in frontend helpers and the Worker routes. Holiday administration changes the rule record; existing appointment rows are not converted into holiday records. Import is not available, so a CSV import conflict workflow is not part of this build.

SECTION 08

Security & access boundaries

  • Worker routes require a valid session for non-public API calls; authentication uses an HttpOnly cookie and server-side token hashes in sessions.
  • Production sessions use the HttpOnly qa_session cookie: 12 hours by default or 30 days with Remember Me. The browser does not store that server session token in localStorage. The local Vite-only auth fallback uses browser storage to emulate users when the Worker API is unavailable; do not treat that fallback as production authentication.
  • Password values are hashed with per-user salt in Worker auth handlers; password reset removes that user's server-side sessions.
  • Public registration is gated by REGISTRATION_CODE. Keep the secret in Cloudflare secret configuration, never in the repository or browser bundle.
  • Repository API routes authenticate sessions. Do not assume that a UI tab restriction is an authorization rule; confirm server-side checks before relying on role-based access.
  • Worker rejects cross-origin requests based on Origin and Fetch Metadata checks. Review deployment behavior whenever changing origins or proxy topology.
IT ownership: confirm account access, secret ownership, backups, session policy, registration policy, logging retention, and incident contacts during handover. This guide cannot verify live account settings.
SECTION 09

Operations and maintenance

  • Before a production migration, compare remote schema state against migration history and take the approved backup.
  • Use Wrangler's intended Cloudflare account/profile. Never assume the local login points to the correct company account.
  • For release, build, deploy, then verify login, current month Schedule load, appointment read/write, holiday rule behavior, Table filtering/export, and History visibility.
  • For rollback, coordinate Worker version rollback and database forward-fix/restore separately; rolling back JavaScript does not reverse a D1 migration.
  • Review dependencies, compatibility date, D1 binding, `dist` assets setting, and any required secrets when transferring ownership.
SECTION 12

Troubleshooting

Symptoms seen in operation, their usual cause and the fix.

Login resets after refresh in Microsoft Edge

Check whether the browser is InPrivate or configured to clear cookies/site data on close. Session persistence uses an HttpOnly cookie and server session; localStorage is not the auth source. Use a standard Edge window and check cookie policy, expiration, Worker session lookup, and system clock.

Cannot schedule on a date / some sites are blocked

Open Manage → Holidays and inspect the date rule. Public Holiday blocks both audit types; No Customer Audits blocks CS; Shutdown Plant applies the selected locked-site list and may still allow IA for non-locked sites. Also check existing assignment conflicts and date validation.

New Data or Complete Data shows an unexpected color

Colors are driven by the status resolver, required-field completeness, created/updated timestamps, appointment date, and result fields. Inspect resolveAuditStatus and the specific assignment payload in src/types.ts / D1. Updated records may take precedence over the new-record window.

Holiday import reports an error or is unavailable

Holiday Excel/CSV import is not present in this build. Add/edit rules through Manage → Holidays. The app API handles one or multiple holiday records through /api/holidays; do not bulk-edit production D1 without a reviewed import plan and backup.

Worker reports missing D1 binding, migration, or table errors

Confirm DB binding and database name/ID in the intended Wrangler environment. Check migration status and apply ordered migrations to the correct database. Compare migration files to deployed schema; do not rerun ad hoc SQL blindly.

Excel .xlsx export does not download

Allow downloads for the app origin in Edge/Chrome, check the browser download panel, and retry after filtering a smaller dataset. If no file is produced, inspect browser console errors and XLSX export code/dependencies. Export follows the filtered table view.

Page loads but API data fails

Static assets can load while Worker/D1 requests fail. Inspect Network responses for /api/state, session status, Worker logs, and D1 binding. A 401 indicates authentication/session; a 5xx suggests Worker or database errors.

สถานะที่คำนวณสีสรุปเงื่อนไข

สถานะคำนวณจาก resolveAuditStatus และ helper ใน src/types.ts การ์ดและแถวตารางใช้พื้นสีอ่อนตามสถานะ พร้อมแถบข้างสีไซต์ สีไซต์กำหนดได้จาก options; ค่าเริ่มต้นครอบคลุม 7 ไซต์ ให้ยึด resolver ใน source เมื่อสีไม่ตรงตามคาด

กฎของช่องวันในปฏิทิน

  • Public Holiday: ปิดการลงทั้ง Customer Audit และ Internal Audit ในวันนั้น
  • No Customer Audits: ปิด Customer Audit (CS); Internal Audit (IA) ยังลงได้
  • Shutdown Plant: ปิด CS; อนุญาต IA เฉพาะไซต์ที่ไม่ได้ล็อกไว้
  • Working Day: override วันหยุดตามปฏิทินให้กลับมาลงตารางได้

กฎอยู่ใน custom_holidays และตีความใน src/holidays.ts ตรวจไซต์ที่เลือกและวันที่ก่อนบันทึก shutdown

Validation และการไม่ทำลายข้อมูลเดิม

การตรวจข้อมูลนัดหมายและข้อจำกัดของวันทำผ่าน frontend helpers และ Worker routes การแก้ holiday เปลี่ยนเฉพาะ record กฎ ไม่แปลง assignment เดิมให้เป็นรายการวันหยุด ไม่มี flow นำเข้า CSV ในรุ่นนี้

SECTION 08

ความปลอดภัยและขอบเขตสิทธิ์

  • Worker บังคับใช้ session กับ API ที่ไม่ใช่ public; auth ใช้ HttpOnly cookie และเก็บ token hash ฝั่ง server ใน sessions
  • Production ใช้ HttpOnly cookie ชื่อ qa_session: 12 ชั่วโมงตามปกติ หรือ 30 วันเมื่อเลือก Remember Me เบราว์เซอร์ไม่เก็บ server session token ใน localStorage ส่วน auth fallback สำหรับ Vite ในเครื่องจะใช้ browser storage จำลองผู้ใช้เมื่อ Worker API ใช้ไม่ได้ ห้ามถือ fallback นี้เป็นระบบยืนยันตัวตน production
  • รหัสผ่าน hash ด้วย salt ของผู้ใช้ใน Worker; การเปลี่ยนรหัสผ่านจะลบ session ที่ใช้งานอยู่ของผู้ใช้นั้น
  • สมัครผู้ใช้สาธารณะต้องมี REGISTRATION_CODE เก็บ secret ใน Cloudflare ห้ามใส่ใน repository หรือ bundle ของเบราว์เซอร์
  • API ใน repository ตรวจ session อย่าสรุปว่าการซ่อน tab ใน UI คือการบังคับสิทธิ์ ต้องตรวจ server-side ก่อนพึ่งพาการจำกัดตาม role
  • Worker ปฏิเสธ request ข้าม origin จาก Origin และ Fetch Metadata ตรวจซ้ำเมื่อเปลี่ยนโดเมนหรือ proxy
การรับมอบให้ IT: ยืนยันผู้ดูแล account, secret, backup, นโยบาย session/registration, การเก็บ log และช่องทางแจ้งเหตุ เอกสารนี้ยืนยันการตั้งค่า live account ไม่ได้
SECTION 09

การปฏิบัติงานและบำรุงรักษา

  • ก่อน migration production เปรียบเทียบ schema remote กับประวัติ migration และทำ backup ตามที่อนุมัติ
  • ใช้ Wrangler account/profile ที่ถูกต้อง อย่าสมมติว่า login ในเครื่องผูกกับ account บริษัทที่ถูกต้อง
  • หลังปล่อยระบบตรวจ login, โหลด Schedule เดือนปัจจุบัน, อ่าน/เขียนนัดหมาย, กฎวันหยุด, กรอง/ส่งออก Table และการเห็น History
  • การย้อน Worker version กับ rollback/restore ฐานข้อมูลเป็นคนละขั้น การย้อนโค้ดไม่ได้ย้อน D1 migration
  • ตอนรับมอบตรวจ dependencies, compatibility date, D1 binding, การตั้งค่า assets dist และ secrets ที่จำเป็น
SECTION 12

การแก้ปัญหา

อาการที่พบ สาเหตุที่พบบ่อย และแนวทางแก้ไข

รีเฟรช Microsoft Edge แล้วหลุดจากระบบ

ตรวจว่าใช้ InPrivate หรือเปิดลบ cookies/site data เมื่อปิดเบราว์เซอร์หรือไม่ session ใช้ HttpOnly cookie และ server session ไม่ได้ใช้ localStorage auth ให้ใช้ Edge หน้าต่างปกติ ตรวจนโยบาย cookie วันหมดอายุ การตรวจ session ของ Worker และเวลาระบบ

ลงตารางไม่ได้ในบางวันหรือบางไซต์

ไป Manage → Holidays แล้วตรวจ rule ของวันนั้น Public Holiday ปิดทั้งสองประเภท; No Customer Audits ปิด CS; Shutdown Plant ใช้รายชื่อไซต์ที่ล็อกและอาจให้ IA ลงได้ในไซต์อื่น ตรวจรายการนัดซ้ำและ validation วันที่ด้วย

สี New Data หรือ Complete Data ไม่ตรงที่คาด

สีมาจาก resolver, ความครบถ้วนของ required fields, created/updated timestamps, วันที่ตรวจ และผลตรวจ เปิดดู resolveAuditStatus และข้อมูล assignment ใน src/types.ts/D1 รายการที่แก้ไขใหม่อาจมี priority เหนือช่วง New Data

นำเข้าวันหยุดแล้วเจอข้อผิดพลาดหรือหาเมนูไม่พบ

รุ่นปัจจุบันยังไม่มี Excel/CSV holiday import ให้เพิ่ม/แก้ใน Manage → Holidays API ใช้ /api/holidays สำหรับหนึ่งรายการหรือหลายรายการ อย่าแก้ D1 production โดยตรงโดยไม่มีแผนและ backup ที่ผ่านการตรวจ

Worker แจ้งว่าไม่มี D1 binding หรือไม่พบตาราง

ตรวจ binding DB และชื่อ/ID ฐานข้อมูลใน Wrangler environment ที่ถูกต้อง ตรวจสถานะ migration และใช้ไฟล์ migration ตามลำดับกับฐานข้อมูลเป้าหมาย เปรียบเทียบ schema ที่ deploy แล้วก่อนรัน SQL ซ้ำ

ส่งออก Excel .xlsx ไม่ได้

อนุญาตดาวน์โหลดสำหรับ origin ของระบบ ตรวจ download panel ของ Edge/Chrome แล้วลองใหม่ด้วยชุดข้อมูลที่กรอง หากไม่มีไฟล์ ตรวจ console error และโค้ด/แพ็กเกจ XLSX การ export ใช้ผลจากมุมมอง Table ที่กรองแล้ว

หน้าเว็บขึ้นแต่ข้อมูล API โหลดไม่ได้

static asset อาจโหลดได้แม้ Worker/D1 มีปัญหา ตรวจ Network ที่ /api/state, สถานะ session, Worker logs และ D1 binding 401 มักเป็น session/auth; 5xx ชี้ไปที่ Worker หรือฐานข้อมูล
